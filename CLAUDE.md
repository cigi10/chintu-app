# Project conventions

- **No em dashes (—) in any user-facing copy, ever.** This includes JSX/TSX text content, placeholders, metadata descriptions, alt text, error messages, and content/blog and content/quiz JSON — anywhere a string renders to a user. Use a period, comma, colon, or parentheses instead, whichever reads most naturally. Code comments and test descriptions are exempt (they're not user-facing), but don't rely on that exemption to be lazy in new UI copy. This has already needed a full sitewide sweep twice (Batch 11 covered blog/quiz content only; Batch 15 covered everything else) — check new copy before it ships instead of letting it recur a third time.
